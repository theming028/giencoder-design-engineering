### 方案核心
- **定位**：设计系统 4 层已有 3 层（L1 tokens / L2 契约×71 / L4 页面模式×6），缺 **L3 页面描述层**。
- **薄 DSL 原则**：只描述「结构 + 组件引用 + props + 数据」，样式全部封在 L1/L2 —— token 合规变成编译期保证。
- **语法**：YAML（`*.yq.yaml`），节点规约 `c/props/text/slots/tree/when/render`；`c` 必须在 registry、props 必须命中契约 `propsIndex`（与 sync-props.py 同源，不另维护规则）。
- **编译器**：`yq build`（Python，5 步：parse → validate → resolve → codegen → emit），片段从 preview 模板抽取生成（防双源漂移），产物走 serve.py + puppeteer 惯例。
- **AI 闭环**：上下文包（schema + 契约摘要 + few-shot，~10K tokens）→ LLM → DSL → 校验失败自动回喂重试 ≤3 轮 → 编译 → 截图人验收。
- **路线**：P0 POC（list-page 单模式，1 次会话）→ P1 六模式 → P2 AI 管线 → P3 逆向编译。

### 对抗式审查要点

- 关键假设「DSL 比 HTML 更稳」未经本地实测 —— P0 即验证动作。
