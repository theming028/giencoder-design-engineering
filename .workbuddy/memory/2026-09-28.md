### 根因（React bundle 内，一处逻辑同时解释两个现象）
路由函数（@169265）：
```js

// Ct() = protocol==='file:'  ;  N() = hash 去 # 后，空则回落到 '/'
```

非 file 协议走 `N()` 读 **hash**；而 Electron 预览 URL **不带 hash** ⇒ `N()`=`/` ⇒ 路由 `/` = `base.html` ⇒ 渲染 **base 壳**。


1. **aside**：只有 base 壳才渲染侧栏
2. **指示器错位**：`en` 组件的 `h(e)` 用 `activeTab='base'` 定位胶囊 ⇒ 白胶囊 `left:2px`（盖住「基础」）；而 r25 补丁 `reconcile()` 又把文字改成「研发工作台」高亮 ⇒ **胶囊与文字错位**

### 通用经验（已写入 MEMORY.md 十八～二十节）

- **显示/隐藏类元素的微动效**：`display` 不可过渡 → ① 外框 `clip-path: inset(0 0 0 Npx round <同 border-radius>)` 做方向性抹开（**必须带 `round`，否则圆角被切**）② 内层元素 `translateX` 做跟手位移（靠父级 `overflow:hidden` 裁剪，零溢出）。比直接 `translateX` 整栏安全 —— 本页 `.td-browse` 右缘已贴外壳内缘，整栏位移会被裁出缺口。
- **折叠内容底部渐隐**：用 `mask-image: linear-gradient(... calc(100% - var(--fade)) ...)` + 变量而不是盖一层渐变 `::after`；展开时变量归 0，两端 `calc` 结构一致即可随 `transition` 插值。
- **DS 源 ↔ 页面内联副本会漂移**：组件在页面里「看起来没样式」时，先在页面里搜该类的 CSS 规则**是否存在**（`grep '.giencoder-xxx {'`），再去 DS 源找参考实现。r53 第 7 项就是这样定位的。
- ⚠️ **`agent-browser wait <ms>` 会丢页面状态**（点击后 `wait`，随后的 `eval` 读到的 `is-browse` 又没了）。
  要等一帧：**分成两次 `eval`**（各自是一个新进程，天然隔 ~200ms），或直接把 `.giencoder-popup-open` / `.giencoder-panel-open` 类补齐再截图。
  取证「开态」必须确认 `opacity=1`（DS 在 rAF 里加类，同一个 eval 里量必然还是 0）。
- **动效取证手法**：`el.style.animationDelay='-0.09s'; el.style.animationPlayState='paused'` 可把动画**定格**在任意时刻截图；
  对照组（改动前）同法定格会得到 `animationName=none`、三帧完全一致 —— 这就是「生硬」的可视证据。

### r56 —— 一个真实缺陷：Esc 收菜单会连带收起整个文件侧栏（`mg-work/r56/apply56.py`）

**现象**：右键菜单打开时按 Esc → 菜单关了，`.td-browse` 也从 944 变成 0，代码预览区 rect 归零。

**根因（三层，务必记牢）**
1. 页面里有**两处独立的 Esc 监听**：① 页尾那条「Esc 优先级链」（注册最早）；② 浏览侧栏自己在**首次打开侧栏时**才注册的 `if (e.key==='Escape' && root.classList.contains('is-browse')) setOpen(false)`。
2. 监听器都在 `document` **冒泡段**，**执行顺序＝注册顺序** → 链条先跑、侧栏监听后跑。
3. 链条一跑就 `dispatch('td:close-ctx')` → 菜单侧 `close()` → `flag(false)` **同步摘掉** `data-td-ctx-open`；
   等侧栏监听再跑时，无论读状态位还是读「菜单侧打的标记」都已经晚了 → 照旧收侧栏。

**修法（与监听顺序无关）**：**标记必须由最先决策的那一环来打** —— 在链条的 ctx 分支里、
`dispatch` **之前**写 `ev.__tdCtxHandled = true;`（菜单侧 keydown 那条也打一份，作为「链条对 INPUT/TEXTAREA 提前 return」时的兜底），
侧栏监听改判 `!e.__tdCtxHandled && !hasAttribute('data-td-ctx-open')`。

**验证**：12 项断言全绿，含反向用例「菜单未开时 Esc 照常收侧栏」。
另外发现：**侧栏开着但无菜单时按 Esc 会跳到 kanban**（链条末尾 `location.href='kanban.html'` 兜底，链条里**没有** browse 分支）——

### 本轮方法论沉淀（五条硬坑，含两条工具级）

1. **agent-browser 的 `hover <sel>` 命令落点会偏**（本轮实测鼠标落到顶栏 HEADER，`:hover` 完全不在目标元素上），
   **不能**作为伪类态取证依据。可靠做法：`getBoundingClientRect()` 拿视口坐标 → 用 CDP 派发
   `Input.dispatchMouseEvent {type:'mouseMoved'}`（发两次、间隔 150ms，更稳）。
2. **CDP 必须先按 URL 选对 page target**：本机同时存在多个 page target —— 带 `?fresh=N` 的同名页、`chrome://newtab/`、
   真正的目标页。`pages.find(p => /task-detail/.test(p.url))` 会**误命中第一个**（`?fresh=4` 那个布局不同），
   于是事件派发到了另一个文档。**用 `p.url.endsWith(文件名)` 精确匹配**。
3. **Node 模板字符串里 `\b` 是退格符转义**：注入 JS 写成 `` `/td-bf\b/` `` 会变成 `/td-bf<BS>/`，永不匹配（且不报错，

4. **`matches(':hover')` 的祖先链会一并命中**：`pick` 正则必须**锚定元素本体**（`^td-bf(\s|$)`），
   否则会先命中 `td-bf-name` 子 span（其 `background` 是 transparent）→ 误判「hover 没生效」。
5. **右键行会顺带置 `is-active`**（r54 设计），激活底色由 `::before` 覆盖整行 ⇒ **激活行看不到 hover 色差**。

### ★ 先取「原文」再动手（重要方法论）
抓文档页拿不到源码。**官方 registry JSON 里有 verbatim 源码**：
```
https://motion-primitives.com/c/text-shimmer.json   →  files[0].content
```
原版机制（照抄，不靠记忆）：
- `className`: `bg-[length:250%_100%,auto] bg-clip-text text-transparent`

- `initial backgroundPosition '100% center'` → `animate '0% center'`

- `dynamicSpread = children.length * spread(spread 默认 2)` → 写进 `--spread`（px）

### ★ 保真度坑：背景盒必须贴住文字
原版元素是 **`inline-block`**（盒子贴字）。本页 `.kb-card-title` 是**块级，实测宽 292px**，
而文字墨迹只有 ≈154px。用 `background-size: 250% 100%` 反推：
- 撑满（292px）：光带中心从 -73px 扫到 +365px → 落在文字区 `[0,154]` 的占比仅 **≈35%**
- 贴字（162px = 文字154 + padding-right 8）：占比回到 **≈63%**（原版约 67%）

⇒ 加 `width: fit-content` 后 `titleRect` 从 292×22 变 **162×22**，兄弟元素各自成行、文字起始 x 均不变。

**相位 ↔ 可见性模型**（可用来解释/预测任一张抓帧）：
光带中心(元素坐标) = `-1.5W·pos + 1.25W`，W = 元素宽 ⇒ 落在文字区当 `pos ∈ [0.2, 0.833]`。
