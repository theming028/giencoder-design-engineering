### ★ 技术发现：`@property` 让 `radial-gradient` 的圆心可动画（实测通过）
`radial-gradient(circle 190px at var(--dx) var(--dy), …)` 的圆心若要随 keyframes 移动，
`--dx/--dy` **必须用 `@property` 注册类型**，否则 keyframes 里改值不插值（瞬间跳变）：
```css
@property --dx { syntax: '<percentage>'; inherits: false; initial-value: 26%; }
@keyframes wand { 0%,100%{--dx:24%;--dy:30%} 25%{--dx:72%;--dy:26%} }
```
实测 `getComputedStyle(el).maskImage` 的圆心由 `26% 32%` 插值到 `47.9983% 28.0001%` ✅
（Chromium/Electron 均支持；项目里已有 `@property --border-beam-angle` 先例）。

### ★ 本轮最大的坑：页尾同步脚本 + React 异步挂载
第一版 JS 直接 `document.querySelector('main.dot-bg')` → **返回 null**，监听器永远绑不上。
原因：脚本在 `</body>` 前**同步执行**时，外壳的 React 还没把 `main` 渲染出来。
症状极具迷惑性 —— CSS 全绿、`transitionProperty` 正确、伪元素 mask 也在，**就是光斑不动、变量恒为初始值**。
⇒ 正解：**文档级事件委托** `document.addEventListener('pointermove', e => e.target.closest('main.dot-bg'))`，
不必等渲染、也不用 MutationObserver。

### ★ 三个 `@property` 硬约束（本轮全部流血验证）
1. 想让 **transition 对自定义属性生效** ⇒ 必须 `@property` 注册类型，否则瞬间跳变；
2. **JS 改不了伪元素样式** ⇒ 变量写在 `.dot-bg` 上，**`inherits` 必须为 `true`** 才能传给 `::before`；
3. transition 写在**主元素**上才可靠（值平滑后再被伪元素继承），别写在伪元素上。

**本轮新踩的坑（已沉淀进 PLAYBOOK）**：
1. ★★★ **`@container` 块必须排在本节所有被覆盖基础规则之后**——否则「部分生效、部分失效」。
   r71 首次落地时 `@container(max-width:560px)` 里 `.av-main-avatar` 生效了（104→72）、
   `.av-main-grid` 却没生效（仍 `147px 147px`），因为前者的基础规则在它之前、后者在它之后。
   同特异性下**后出现者胜**。正解：整组容器查询搬到该 `<style>` 块**末尾**（r36 注释本就写明了这条约定）。
2. ★★★ **clamp 类逻辑必须区分「期望值」与「生效值」**——否则「棘轮」。
   原代码只有一个 `panelW`，resize 处理里 `setPanelW(panelW, false)` 把压缩后的值写回期望位
   → 一旦缩小就永久缩小。改前不会出现（那时 MIN_PANEL = DEF_PANEL = 641）；r71 把 MIN_PANEL 降到 561
   才暴露。正解：`wantPanel`（只由 恢复记忆/拖动/键盘/双击 改写）+ `panelW = clamp(wantPanel, …)`。
   **注意调用点不止一处**：`clampNow` / `setOpen` / 「显示文件目录」切换 共 3 处，
   第一次只改了 2 处，自检立刻抓到。
3. ★★ **真实按键 ≠ 合成 KeyboardEvent**（`isTrusted`）：用 `dispatchEvent(new KeyboardEvent('keydown',{key:'Escape'}))`
   得到的结论**可能是错的**。之前误判「base 权限弹层按 Esc 会跳走」；
   改用 `agent-browser press Escape`（真实按键）实测 → **base 不跳、弹层保持打开**；
   而 task-detail 浏览态真实 Esc **确实跳 kanban**（改前基线同样跳，属既有行为）。
4. ★★ **verify-design 两条独立正则**：`font-?size[`:]*\s*(\d+)px` 与 `(?:animation|transition)[^;}`]*?(\d+)ms`。
   可变数值（随容器缩放的字号、需要 >300ms 的环境动效）用**自定义属性**承载
   （`--av-face-size`、`--nc-glass-dur`）——与同块已有的 `--nc-glass-ease` 同一写法，
   并在注释里显式写明 craft.md 的例外口径。
5. **newmark 撞既有规则 → 误跳过**：`border-radius: 8px;\n box-shadow: var(--shadow3-down);` 这个 newmark
   撞上了 `.td-ctx` 里已存在的同类文本，导致「更多操作菜单 5px→8px」被判定已应用而跳过。
   → newmark 必须绑到**目标选择器的上下文**（`width: 130px; padding: 4px; …`）。
6. **元守卫要分两类**：页面级注入（整块 `<style>` 追加到 `</body>` 前）只禁 `</body>`/`</html>`
   并要求 `<style>` 自配平；块内注入才禁全部标签。注释里写 `</style>`/`<style>`/`:has(...)`
   都会踩「注释污染断言 / 触发元守卫」。
7. **`.skills-popup-bg` 是 9 页共享 CSS 里一份「漏网」大浮层**（`/* 技能选择浮窗 */`，760×320，
   由 `buildSkillsPopup()` 构建、只在 `window.__showSkillsPopup()` 测试钩子下可见）——
   与已改成 8px 的 `.td-skill-pop` 是**同一个 760×320 技能面板**，留着 12px 会出现「同组件两种圆角」。
   **教训：枚举「全局同类对象」时要按 selector 做规则级精扫，别只按肉眼可见的入口枚举。**
