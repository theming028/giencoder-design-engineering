### 三、关键判断与技术坑

1. **① 是「零改动」修法** —— `fold()` 工厂**本来就支持** `data-r93-open` 由 `(o.open === false ? '0' : '1')` 派生。
   **连带**：`wire()` 只给「**初始就展开**」的块挂 `.is-free` ⇒ 收起态本就不挂、无需改。⇒ PLAYBOOK **P3.38②**。

2. **② 不能改源件** —— `part105/browse.css` 与源页 `avatar.html` **逐字节同源**；且 `.r93-bar` **只存在于本页**
   ⇒ 高度适配**只写本页适配层**。⇒ P3.38③。

3. **③ 两个反直觉点**：`main` 圆角**只暴露在右缘**（左边贴左导航）⇒ 改前与面板左缘间**漏 10px 缺口**；
   接缝改前是**两条 1px 并排**（x=790 `#ECEEF2` = main 右框、x=791 `#E5E5E5` = 面板左框）⇒ **线归面板**。
   ⚠ Tailwind `border` 按 **border-box** ⇒ `border-right-width: 0` **只让内容盒宽 1px、边框盒仍 779**。⇒ P3.38⑤。

4. ★★ **④ 首拍判错了口径**：邵先生原话是「**分辨率不足时（如 1440）才自适应；空间足够时保持之前逻辑**」，
   首拍理解成**无条件撑满**（1440/2560 都吃满）⇒ 返工拍改正。
   * **原逻辑实测**（`ev/p106e.js` 把覆盖摘掉读真值）：`.r93-wrap` = `max(50% × main内宽, 860px)`，
     且因父盒带 gutter，页内既有约定是 `calc(50% + 10px)` 补偿基数差。
     ⇒ 1440 开态原值 **860**（可用仅 758 ⇒ **右溢 92px 被裁** = 「遮挡」）；2560 开态原值 **949**。
   * **修法三个坑**（P3.38⑥）：
     a) **`margin: 0 auto` 不能居中** —— 元素宽 > 包含块时 `auto` 在溢出方向**只退化成 0**
        （实测原逻辑 `mL 0 / mR −102` 不对称）⇒ 必须显式 `calc((100% − 宽)/2)`（撑满时正好 = −10px）。
     b) **原表达式要连「基数补偿」一起抄** —— `.r93-wrap` 的 `50%` 基数比 `.r93-bottom` 少 20px
        ⇒ 页内约定 `calc(50% + 10px)`；只抄 `max(50%, 860px)` 会让四列差 10px（r97「全宽块等宽」破）。
     c) **必须同时 `min-width: 0`** —— 原规则的 `min-width: 860px` 会把 `min()` 结果顶回去。
   * **判据是「容器可用宽」不是视口分辨率**（预览栏开/关、左导航收拢都会改它）⇒ 用 `@media` 断点会在「开了预览栏的 2560」上误判。

5. ★ **⑤ 的根因 = 内联样式优先级最高**：模板对第 2 张卡写了**内联** `color`，
   把 CSS 里既有的「默认 text-1 / hover primary-6」整条压死 ⇒ 删内联即可（CSS 未动）。
