## Table 排序 SVG 改为单向箭头（避免"还会翻转"错觉）

- 反馈：用户说"排序按钮能排序了，但点击后还是会翻转"。
- 根因：原 SVG path 是双向箭头（`M4 1l2.5 3h-5L4 1z M4 11l-2.5-3h5L4 11z`，上下各一个三角形）。即使 asc 状态 transform=none 不旋转，视觉上仍然显示"上下都有"，与之前 .yuanqi-table-sorter-active 旋转后的双箭头几乎一样 → 用户感知"还是会翻转"。
- 修复：只保留上方三角形（`M4 1l2.5 3h-5L4 1z`），下方留空。
  - none → 灰色▲（指上）
  - asc  → 蓝色▲（指上，不旋转）
  - desc → 蓝色▼（旋转 180°，从▲变▼）
- 语义重映射：颜色区分激活态（灰/蓝），方向区分升降序（上/下）。"翻转"视觉现在只在 asc↔desc 之间发生（▲→▼），符合 TDesign 与主流组件库惯例（Element Plus / Ant Design 排序图标都是单向）。
- 顺带补 `stroke-linejoin=round` 让三角形顶点圆润。
- 提交 `94763da`：2 files / +10 / -2，推送成功 00eea57..94763da。
- 教训：**单向图标 + 旋转 180° 是排序的标配**。SVG path 不能凭直觉画——双向箭头即使在某些态下不旋转，视觉仍像"双向"，会破坏"none→asc 无变化、asc↔desc 翻转"的用户预期。设计图标时，"形状 = 状态"而非"颜色 = 全部状态"，更符合用户认知。
## Table 排序图标彻底静态化（解决"还是会翻转"）

- 反馈：用户第二次说"还是会翻转"，前两次修（双向→单向 SVG、加三态切换）用户仍感知为"翻转"。
- 决策：放弃在图标层做反馈，干脆让图标**完全静态**——始终灰色指上，无颜色变化、无旋转变化。
- 改动：
  - components.css：删除 `[data-sort="asc|desc"]` 的主色高亮 + `rotate(180deg)`，仅保留 sorter 默认灰（--color-text-4）
  - preview 行内：删除 sorter / svg 的 transition（无变化不需要过渡）
  - table.json：interaction.sort 描述改为"默认图标保持静态，仅靠 data-sort + 数据重排表达"，并保留"调用方如需视觉反馈"的覆盖示例
- JS 不变：仍按 none→asc→desc→none 状态机循环，仍按业务权重（已停止<待处理<运行中）重排 tbody
- puppeteer 4 步验证全过：
  - 4 状态下 sorterColor = rgb(201,205,212)=text-4 灰（不变）
  - 4 状态下 svgTransform = none（不变）
  - sortAttr = none→asc→desc→none（状态机正常）
  - rowsState = A/B/C/D ↔ C/B/A/D ↔ D/A/B/C ↔ A/B/C/D（数据确实重排）
- 提交 `6e5a9c9`：6 files / +18 / -18，推送成功 94763da..6e5a9c9。
- 教训：**当一个 UI 反馈反复被用户感知为"错误/奇怪"时，要么修到用户感知对、要么干脆去掉该反馈**。本次属于后者——视觉反馈是 nice-to-have，没有它功能仍然完整（数据已重排 + data-sort 属性已设置 + 调用方可通过自定义选择器恢复反馈）。"过度反馈"和"反馈缺失"相比，过度反馈更难调试。
