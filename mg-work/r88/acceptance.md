## 二、第 2 条的根因（取证留痕）

| 事实 | 证据 |
|---|---|
| 命中层只有 **1 device px 高** | r87 版 CSS：`.r85-sl-track{ width:240px; height:1px }`，而 `click` 监听**挂在 track 上** |
| **完全没有拖拽实现** | r87 版 JS 里只有 `wrap.addEventListener('click', …)`（点击即跳档），无 pointerdown/move/up |
| 结论 | 「拖不动」不是手感问题，是**没有可拖的代码 + 几乎点不中** |

修法要点：
1. **命中层**：`.r85-slider{ cursor:pointer; touch-action:none; user-select:none }` + `.r85-slider > *{ pointer-events:none }` ⇒ 整块 252×36 都能按下（含轨道上下各 17px）。
2. **move/up 挂 `window` 而不是 wrap**：`setPointerCapture` 万一失败（合成事件/异常），只挂 wrap 会在指针移出元素后收不到事件 ⇒ `dragging` 永卡 `true`（之后划过就误拖）。挂 window 两种情况都收得到。
3. **拖动中不落盘**：`setIdx()` 只写 `--ui-fs`（视觉），`pointerup` 才 `fsApply(idx, true)` 写 `localStorage` + toast ⇒ 拖过 6 档只提示一次。
4. **键盘可达**：`tabindex=0` / `role=slider` / `aria-valuemin/max/now/valuetext`；↑↓←→ 步进、Home/End 到端点；`:focus-visible` 主题色光圈（`outline-offset:2px`）。

### 第 3 条的根因（逐像素留痕）

实测设计稿（行 2，device 2x）

```
 y10 |      .#######.              ← 标签顶边（宽 8 device）
 y11 |     .#########.
 y12 |     .#.     .##            ← 标签右侧**竖边**（不是斜边）
 y13 |     .#.      .##########+  ← 本体顶边
 y18 |     +####################+ ← 中部横线（全宽）
 y28 |     .####################. ← 底边
```
⇒ 设计稿图标 = **近似方形**（墨迹 21×20 device = 10.5×10 design px）、标签是**直角台阶**、中部横线在 46% 高。

原实现是 16 网格的 `i_folder`（`M2.3 12.9V4.3h3.2l1.3 1.6h7v7z`）**缩到 12px** 用，三处叠加导致「异常」：

| 问题 | 数值 |
|---|---|
| ① 比例错：墨迹只有 **8.6×6.5px**（设计 10×10）⇒ 明显**扁**且偏小 | 0.75 倍缩放 + 路径本身只占 11.5×8.6 单位 |
| ② 标签用了**斜边**（`l1.3 1.6` ⇒ 实际 1.2px）⇒ 0.75 倍下糊成一坨，看不出台阶 | 设计稿是竖边直角 |
| ③ 描边 `stroke-width:1.5` 单位 × 0.75 = **1.125px**，且坐标不落在半像素 ⇒ 1px 描边被摊到 2 行像素上发虚 | 无一处整像素对齐 |

**修法（可复用配方）**：小尺寸图标**按渲染尺寸建 1:1 网格**——
`viewBox="0 0 12 12"` + 渲染 `12px` ⇒ **1 单位 = 1px**；坐标全部取 **x.5**（1px 描边正好盖满整数像素区间 `k..k+1`）；直角用 `h/v`，不用斜边。
```js
'i_folder12': '<svg viewBox="0 0 12 12" fill="none">'
  '<path d="M1.5 1.5h4v2h5v7h-9z" stroke="currentColor" stroke-width="1"/>'   /* 外框（标签直角台阶） */
  '<path d="M1.5 5.5h9" stroke="currentColor" stroke-width="1"/>'            /* 中部横线 */
  '</svg>'
```
