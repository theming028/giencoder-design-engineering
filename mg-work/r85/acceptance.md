## 三、本轮打通的设计稿取数链路（重要）

1. **★ `GET http://127.0.0.1:30678/api/getScreenshot` 能直接拿节点 PNG（base64）**
   `…/api/getScreenshot?documentId=193158744355579&documentPageId=ip148:02203&targetNodeId=<节点>&scale=2`
   首次 21.7s、二次 0.38s（有缓存）。**必须 GET + query**（POST 一律 400）。
   - `20678` = MCP（JSON-RPC）；`30678` = mgmcp 的 HTTP server（`/api/*`）。
     PLAYBOOK 旧记「30678 的 HTTP 全是 400」是**只试了 GET 根路径**的片面结论 → 已更正。
   - ⚠ 该接口**返回当前画布选中图层**，传 `targetNodeId=1389:18609` 仍回内容页 —— 导航节点拿不到独立截图。
2. **★ 设计稿里的 `text/title` 是未展开的 DS 实例 ⇒ 结构树里没有文案**（42 个 `ui-component` 只有 7 个带 `text`）。
   喂单个 `text/title` 节点给 `get_selection_node` → 120s timeout。**文案只能从截图读**。
   MCP 工具 `get_screenshot`（带 `projectDir`/`scale`）实测**必 120s timeout**，别用。
3. **★ 导出 PNG 是 RGBA，未绘制处 alpha=0** —— `convert('RGB')` 会把它变成纯黑，极易误判成「MasterGo 标签条盖住内容」。
   本轮一开始就这么误判过。正确做法：`alpha_composite` 到白底后再扫描。
   （顶部 0–52 的逻辑 px 之所以是「黑」，只是因为标题节点无填充 > 该区透明。）

## 四、设计稿逐像素实测（几何依据，非目测）

- 导出图 `design_1389-18725.png` = **1680×1838 = 840×919 × 2**，**1 逻辑 px = 2 device px**。
- **卡片是「内描边」**：左缘 x=0–0.5 为 `#EEEEEE`，x=1.0 起为 `#F8F9FA`；上下同理。
  ⇒ 描边**不占内容盒**（行宽 800 = 840 − 2×20）。CSS 必须用 `outline: 1px + outline-offset:-1px`，
  写 `border` 会让行宽变 798、卡片高多 2px，并把整列 y 推低 2–3px。
- **滑块**：轨道 rel x6 长 240；6 段刻度 rel **6/54/102/150/198/246**（第 2 格被拇指盖住）；
  已选段 48；拇指 4×12 rel x52；刻度 1×8 rel y2；「小/默认/大」中心分别落在 rel **6 / 54 / 246**。
- **卡片3 首行控件组**：复选框遮罩 14×14 @516 → 复选框 76 宽；「更新日志」x604..708、「检查更新」x716..820（各 104×32、1px 描边、间距 8）；

- **文字左缘**：卡片1/2 行内 **52**（墨迹 73），卡片3 两行 **56**（墨迹 77）—— 逐像素证实。
- 色值 → token：开关开 `#3BB346`=`--color-success`、勾选框 `#3770F7`=`--color-primary-6`、
