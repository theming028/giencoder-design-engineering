### ④b 的定位过程（★ 第三拍：从「728」这个数反推元素）

邵先生只给了一个数：**728px**。做法 = **把这个数从页面里揪出来**，而不是先假定是哪个类：

1. **先量 `.r93-wrap`（邵先生 #4 里点名的类）**：1440 关 **860** / 1440 开 **778** / 1370 开 **708** / 1280 开 **618** / 1920 开 **860** / 2560 关 **1141** ——
   **没有任何一档是 728**。⇒ 说明 728 **不是** `.r93-wrap` 的值（`ev/p106i.log`）。
2. **全页扫描「宽度落在 700~760」的元素**（`ev/p106j.log`）⇒ 揪出 `.r93-bub` / `.r93-bubi` / `.r93-attrow`×2 / `.r93-umeta`
   五个盒子，**在 1440 关·开、1370 关·开四种情形下**一律 **728**、一动不动 ⇒「**固定的**」。
3. **全仓 grep `728px`** ⇒ `pages/*.html` 里**仅此一处**：
   ```css
   /* ===================== 用户消息 ===================== */
   .r93-bub { margin-left: auto; width: 728px; display: flex; flex-direction: column; }
   ```
   `ev/p106l.log` 进一步确认：**蓝底气泡本体 `.r93-bubi` 就宽 728**（`BG=rgb(229,237,254)`，`x[552..1280]@1440关`）。
4. **溢出判据**（改前实测）：块是 `margin-left:auto` **右对齐** ⇒ 列一旦窄于 728，它就**向左溢出**、
   被 `.r93-scroll` 的 `overflow:hidden` **裁掉**：

```
1280 开：列 618 / 块 728 ⇒ 溢 110px（气泡断在「…三个泳道，未」，「未开始，进行中，已完成。」整体丢失
                                      + 三枚附件 chip 被切）  ← raw/m106b-1280-open.png

1440 开：列 778 / 块 728 ⇒ 溢 0（但仍有 50px 左空隙）
```

**改法**＝同一条口径的又一次应用：`width: min(100%, 728px)`（**列 ≥728 保持 728、列 <728 跟着收**）。
⚠ **唯一不带 `.av-browse-on`** 的一条 —— 溢出只取决于「列 ↔ 728」的大小关系，**窄窗口的关态同样会溢**。
⚠ 1440 关（860）/ 2560 关（1141）下 `min` 取 728 ⇒ 与 r105 **逐像素一致**；唯一生效区间是「列 < 728」，而那本来就是坏的。

### ④ 的口径更正细节（★ 返工拍最实质的一处）

**邵先生首拍原话**是「展开时 `r93-wrap` 就应该是自适应宽度了，现在还是固定宽度，就造成了部分内容被遮挡」。
首拍的理解 = **无条件撑满**（1440/2560 都吃满）——
**返工拍更正为**：「**当分辨率不足时（如 1440）才应该自适应；当空间足够时保持之前逻辑**」。

* **原逻辑实测**（`ev/p106e.js` 复现）：`.r93-wrap` = `max(50% × main内宽, 860px)`，
  且因父盒带 gutter，页内已用 `calc(50% + 10px)` 补偿基数差（`.r93-bottom` 是 `width: 50%; min-width: 860px`）。
  ⇒ 1440 开态原值 **860**（容器可用仅 758 ⇒ **右溢 92px 被裁**，即「遮挡」）；2560 开态原值 **949**。
* **改法**：写成 `min(可用宽, 原逻辑值)`，**判据是容器可用宽、不是视口分辨率**
  （预览栏开/关、左导航收拢都会改它）⇒ 天然跟着容器走。

```
1440 开：可用 758 / 原逻辑 860 ⇒ min = 778（吃满两侧 gutter，不再溢 92px）
2560 开：可用 1878 / 原逻辑 949 ⇒ min = 949（居中，与 r105 逐像素一致）
```

## 二、六条的关键实现

### ① 「零改动」修法 —— 先查工厂**是否本来就支持**
`fold()` 工厂**早已支持** `open: false`（`(o.open === false ? '0' : '1')` 派生 `data-r93-open`）⇒ 只加一个参数。
连带确认 `wire()`：只给「**初始就展开**」的块挂 `.is-free` ⇒ 收起态本就不挂、**无需改**。

### ② 只覆盖 `height`，**不动源件**
`td-browse-bar` 属 r105 从 `avatar.html` **整块移植**的三件套 ⇒ 源件必须**逐字节同源**（`extract105.py`）；
且 `.r93-bar` **只存在于本页** ⇒ 高度适配**只写本页适配层**。

### ③ 接缝两件事：**归零右两角 + 把线让给面板**
`border-top-right-radius: 0; border-bottom-right-radius: 0; border-right-width: 0`。
⚠ Tailwind `border` 按 **border-box** ⇒ `border-right-width: 0` **只让内容盒宽 1px、边框盒仍 779**
⇒ 面板位置 / 拖拽手感不变。面板左边线是设计稿**专门为接缝另取的一档** ⇒ **接缝的线归面板**。

### ④ 自适应宽的三个技术点

1. **吃回 gutter**：父盒 `.r93-scroll` 带 `scrollbar-gutter: stable both-edges`
   （778 → clientWidth **758**，左右各 10px）⇒ `calc(100% + 20px)` 把两侧讨回来（撑满时 = 778 = `.r93-pane` 内宽）。
2. **上限写原逻辑的等价式**：`max(calc(50% + 10px), 860px)` ——
   `.r93-wrap` 的 `50%` 基数比 `.r93-bottom` **少 20px**，故 `+10px` 补偿；
   这是**页内既有约定**（`.r93-sk-in` 原来也是同款写法），补上四列才同宽。
3. **外距必须显式算，不能用 `margin: 0 auto`**：
   撑满时元素宽 > 包含块，`auto` 在溢出方向只会退化成 0 —— 实测原逻辑给出 `mL 0 / mR −102` 的**不对称**结果。
   ⇒ 写 `margin: 0 calc((100% − 宽) / 2)`：撑满时 = **−10px**（各让出半个 gutter）、居中时 = 真居中量。
4. **四列同口径**：`.r93-bottom` / composer 外壳 / `.r93-sk-in` 的父盒**没有 gutter** ⇒ 口径是 `min(100%, max(50%, 860px))`。
   composer 那条原规则自带 `!important`、特异性更高 ⇒ 靠 `html[data-r93-page] .av-browse-on` 前缀提到 **(0,5,6)** 才压得住。
   ⚠ `.r93-sk-in` 原式 `calc(50% + 10px)` 是按「有 gutter」写的、而它父盒**没有** ⇒ 会宽出 10px，本轮顺手对齐。

### ⑤ 产物卡文件名：**删内联**，CSS 一字未动
模板数据 `['arthov', 'spec-template.md', 1]` 的第 3 位触发
`+ (c[2] ? ' style="color:var(--color-primary-6)"' : '')` ⇒ **内联**是最高优先级，
把 CSS 里既有的「`.r93-artname` 默认 `text-1`、`.r93-artcard:hover .r93-artname` 才 `primary-6`」整条压死。
**修法 = 只删那处内联**（连数据里的 `1` 一并去掉）⇒ 默认回 `text-1`、hover 照旧变蓝。

### ④b 用户消息块：**写死的 728px → 上限型 clamp**（与 ④ 同一口径）
原规则在 r93 段的「用户消息」里：`margin-left: auto`（右对齐）+ `width: 728px`，
**非 `!important`、特异性 (0,1,0)** ⇒ 本页适配层 `html[data-r93-page] .r93-bub` **(0,2,1)** 压得住，**无需 `!important`**。
`margin-left: auto` **保留**：列 ≥728 时维持右对齐；列 <728 时 `width` 取 `100%`，`auto` 自然退化成 0 ⇒ 满行。
`min-width` 不用管：`.r93-bub` 的父盒 `.r93-it` 是 `display:block` ⇒ 块级子元素的 `min-width:auto` 就是 0。
