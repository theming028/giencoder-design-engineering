1. 快速上手（5 分钟）

先跑起来看到东西，再谈怎么做。整个系统是纯静态文件，无需构建。

1.1 打开方式（零配置）

整套系统是纯静态文件：全部 UTF-8 编码，组件库首页、组件预览、Token 规范与本说明书之间都用相对路径互相串联，无需任何本地服务。

最快上手：双击根目录的 GETTING-STARTED.html，浏览器打开即可。所有跳转、iframe 活预览、CSS 样式在 file:// 协议下均正常工作。

三个高频入口（双击打开任一即可，后续跳转皆为相对路径）：

  • 使用说明书：GETTING-STARTED.html（根目录）
  • 组件库首页：giencoder/index.html — 浏览全部 71 个组件
  • Token 可视化：giencoder/tokens-visual.html — 看全部色板/字体/间距
关于 serve.py：根目录的 serve.py 只是一个可选的本地 HTTP 服务（默认端口 8866），只在跨域调试 / 模块化调试等需要 HTTP 协议行为的场景才需要用。日常浏览、组件预览、契约查阅都不需要它。

1.2 三个入口，对应三种需求

我想……去这里
看某个组件长什么样、有哪些变体/状态index.html → 点进对应组件详情页
拿一段能直接复制的组件代码组件详情页右侧即代码模板，或 preview/component-{slug}.html
搭一个完整页面ui_kits/ 六大页面样板，复制改内容

1.3 建议的第一次阅读顺序

  1. 点开 index.html，随便点 3 个组件看详情（如 Button、Table、Modal）
  2. 打开 tokens-visual.html，建立「颜色/字体/间距都有 Token」的直觉
  3. 打开 ui_kits/list-page/index.html，看一个成品页面长什么样
  4. 回到本说明书的「核心概念」与「标准工作流」章节

3. 核心概念

整套系统靠「三件套」运转：契约（规格）→ 模板（代码）→ Token（样式变量）。理解三者关系，就理解了整套系统。

三件套的关系

概念回答的问题落点类比
契约 Contract这个组件应该长什么样、有哪些变体/状态/交互components/{slug}.json设计规格说明书
模板 Template这个组件的代码长什么样preview/component-{slug}.html可直接复制的成品代码
Token颜色/间距/圆角等的唯一取值是什么colors_and_type.css + tokens.md设计变量字典

一句话：契约约束「有什么」、模板给出「怎么写」、Token 锁定「用什么值」。

3.1 契约（Contract）——实现前先读它

每个组件都有一份契约 JSON。以 Button 为例，关键字段：

{ "slug": "button", "category": "general", "variants": [ { "name": "primary", "whenToUse": "页面主操作" }, ... ], "sizes": [ { "name": "medium", "value": "32px 高度" }, ... ], "states": [ { "name": "hover", "visual": "..." }, ... ], "interaction": { "keyboard": ["Enter: 触发"], "motion": {...} }, "a11y": { "role": "button", "ariaAttrs": [...] }, "usage": [ "主操作每屏仅一个", ... ], "doNotInvent": [ "不虚构圆角/胶囊等额外 shape 变体", ... ], "tokensConsumed": [ "--color-primary-6", ... ] }
重点看两个字段：usage（该组件的正确用法）和 doNotInvent（禁止臆造的东西）。它们直接决定你会不会「做错」。

3.2 模板（Template）——复制它，别手写

模板是「可复制的代码」，不是「视觉参考图」。生成页面时，从模板原样复制组件 HTML，只改文字与数据。

原则：先复制模板，再替换内容。手写组件 HTML 是出错的头号来源。

3.3 Token——禁止硬编码

所有视觉取值都来自 Token。颜色用 var(--color-*)，间距用 var(--spacing-*)，圆角用 var(--border-radius-*)，阴影用 var(--shadow*)，动效用 var(--transition-*)。

✗ 错误

color: #3770F7;

硬编码 hex，换主题/改品牌色就失效

✓ 正确

color: var(--color-primary-6);

走 Token，全局联动

3.4 Token 分类速查

类别前缀示例说明
品牌色--color-primary-*--color-primary-61 最浅 → 10 最深，6 为基准
文本色--color-text-*--color-text-1/2/3/4主 / 次 / 辅助 / 禁用
背景色--color-bg-*--color-bg-1 ~ 5层级背景
边框--color-border-*--color-border-1 ~ 4组件边界
功能色--color-success/danger/warning/link--color-success-6含 -light-1/2 浅色背景档
间距--spacing-*--spacing-722 档刻度
圆角--border-radius-*--border-radius-mediumnone/small/medium/large/circle
阴影--shadow*--shadow1-down1/2/3 档 × 方向
动效--transition-*--transition-duration-2含缓动函数

4. 标准工作流（六步）

从需求到高保真页面的固定路径。按顺序走，不跳步。

明确需求与模式

先想清楚要什么页面，对应 patterns.md 六大模式里的哪一种（列表/详情/表单/看板/配置/结果）。页面 = 骨架 + 区块 + 状态 + 反馈。

选组件

在 index.html 按分类（通用/布局/导航/数据录入/数据展示/反馈/其他）找到需要的组件，记下它的 slug。

查契约

读 components/{slug}.json。重点看 variants（用哪个变体）、usage（怎么用）、doNotInvent（别造什么）。

复制模板

从 preview/component-{slug}.html 复制对应片段，只改文字与数据，别改结构。

套 Token + 组页面

所有颜色/间距/圆角/阴影用 var(--*)；按 patterns.md 把区块组合成页面骨架。

校验

用第 7 章验收清单逐项自检：Token 无硬编码、弹层三要素、对比度、状态齐全、响应式。

5. 铁律与反模式

五条铁律是红线，违反任何一条都不算合格产出。下面是每条的常见错误与正确做法。

铁律 1：组件以契约为准，禁止臆造

任何组件先读契约，再动手。不要凭「记忆里这个组件应该能……」来写。

✗ 臆造

「Button 应该有胶囊圆角变体吧，我加一个」

✓ 守约

读 button.json，确认只有 square/circle 两种 shape，绝不新增

铁律 2：Token 禁硬编码

颜色、间距、圆角、阴影、动效一律 var(--*)。代码里出现 hex 色值 = 不合格。

✗ 硬编码

background: #F53F3F; padding: 12px;

✓ Token

background: var(--color-danger-6); padding: var(--spacing-6);

铁律 3：禁止替换类库

不引入外部 CSS 框架、不用 Lucide/Heroicons/FontAwesome 图标、不用 CDN 框架、不自造 SVG 路径。

说明：图标用内联 SVG（源启图标体系），颜色用 currentColor 继承文字色。引第三方图标库会破坏视觉一致性。

铁律 4：弹层必做三要素

Modal / Drawer / Select / Dropdown 等弹层必须实现：focus trap（焦点循环）+ Esc 关闭 + 遮罩点击关闭。

详见 a11y.md §4，每个弹层组件的键盘行为见其契约的 interaction.keyboard 字段。

铁律 5：页面按模式组合，不自由发明布局

页面结构按 patterns.md 六大模式组合，骨架对齐 ui_kits 样板。别自己发明一套「看起来很新」的布局。

反模式速查表

错误做法为什么错正确做法

6. 端到端示例：列表 + 新建表单

用一个真实业务场景「资源管理列表 + 新建资源」完整走一遍六步工作流。最终成品可直接打开 giencoder/ui_kits/list-page/index.html 查看。

6.1 需求

做一个后台「资源管理」页：顶部标题 + 「新建资源」按钮；筛选栏（资源名搜索 + 状态 + 创建时间）；资源表格（勾选/名称/状态/负责人/操作）；底部分页；点「新建」弹出表单（名称/描述/环境/类型/开关）。

6.2 选组件 + 查契约

页面区块组件（slug）分类契约要点
页面骨架Layout + Menu（layout / menu）布局 / 导航Header 48px + Sider 200px + Content
标题栏PageHeader（page-header）导航标题 + 副标题 + 右侧操作区
新建按钮Button（button）通用primary 变体，主操作唯一
搜索框Input（input）数据录入支持前缀图标
状态筛选Select（select）数据录入弹层三要素
表格Table（table）数据展示勾选列 + 操作列
状态标签Tag（tag）数据展示light + success/warning/danger
分页Pagination（pagination）导航页码 + 总数
新建表单Form + Input/Select/Radio/Switch数据录入必填标记 + 校验错误态

6.3 复制模板，拼装页面

页面骨架（顶栏 + 侧栏 + 内容区）：

<!-- 顶栏 --> <header class="giencoder-top-nav" style="height:48px;">...</header> <!-- 侧栏（200px 菜单）--> <aside class="giencoder-sidenav" style="width:200px;"> <div class="giencoder-menu giencoder-menu-vertical"> <div class="giencoder-menu-group-title">总览</div> <div class="giencoder-menu-item giencoder-menu-item-selected">资源管理</div> </div> </aside> <!-- 内容区 --> <main style="flex:1; padding:20px;">...</main>

标题栏 + 新建按钮（PageHeader + Button）：

<div class="giencoder-page-header"> <div> <h2 class="giencoder-page-header-title">资源管理</h2> <div class="giencoder-page-header-subtitle">管理云上资源实例</div> </div> <div class="giencoder-page-header-extra"> <button class="giencoder-btn giencoder-btn-primary giencoder-btn-size-default">新建资源</button> </div> </div>

表格行（Table + Tag + Button）：

<tr class="giencoder-table-tr"> <td class="giencoder-table-td giencoder-table-checkbox"> <label class="giencoder-checkbox"><input type="checkbox" class="giencoder-checkbox-input"><span class="giencoder-checkbox-mask"></span></label> </td> <td class="giencoder-table-td">订单中心微服务</td> <td class="giencoder-table-td"> <span class="giencoder-tag giencoder-tag-light giencoder-tag-success">运行中</span> </td> <td class="giencoder-table-td giencoder-table-operation"> <button class="giencoder-btn giencoder-btn-text giencoder-btn-size-mini">编辑</button> <button class="giencoder-btn giencoder-btn-text giencoder-btn-size-mini giencoder-btn-danger-text">删除</button> </td> </tr>
关键观察：上面所有代码里，没有一个 hex 色值，间距全走 var(--spacing-*)，颜色全走 var(--color-*)。这就是「套 Token」的落地样子。

7. 验收清单

交付前逐项自检。全部勾选才算「高保真达标」。

  • 页面 <head> 引入了 colors_and_type.css 与 components.css
  • 代码中无任何硬编码 hex 色值，颜色/间距/圆角/阴影/动效全部走 var(--*)
  • 每个组件都查过契约，未臆造变体/状态（对照 doNotInvent）
  • 页面结构符合 patterns.md 六大模式之一，骨架对齐 ui_kits 样板
  • 弹层（Modal/Drawer/Select/Dropdown）具备 focus trap + Esc + 遮罩点击三要素
  • 文本对比度 ≥ 4.5:1，焦点环可见（a11y.md）
  • 交互状态齐全：default / hover / active / focus / disabled / loading
  • 列表页有空态、错态、加载态处理
  • 图标用内联 SVG + currentColor，无第三方图标库
  • 窄屏（≤860px）布局不崩、不溢出
一句话自检：能不能仅靠「复制模板 + 改文字 + 用 Token」就复现这个页面？能，就达标。
